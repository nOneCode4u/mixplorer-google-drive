## 🔍 Which APK Should I Download?

| Suffix        | Architecture          | Target Device                                |
| ------------- | --------------------- | -------------------------------------------- |
| *(no suffix)* | Universal / Pure-Java | All devices — works everywhere               |
| `-arm`        | 32-bit ARM            | Older Android phones (before ~2016)          |
| `-arm64` ⭐    | 64-bit ARM            | **Most modern Android phones — recommended** |
| `-x86`        | 32-bit x86            | Older Android emulators                      |
| `-x64`        | 64-bit x86            | Modern Android emulators & Intel Chromebooks |
| `-universal`  | All architectures     | Any device (includes all native libraries)   |

> 💡 **Quick Recommendation:** If you are unsure which build your phone requires, choose the **`-arm64`** variant.

## ❓ Why This Repository Exists

[![Python](https://img.shields.io/badge/Automation-Python-3776AB?style=for-the-badge&logo=python&logoColor=white)](https://www.python.org/)

MiXplorer and its add-ons are primarily distributed via an [XDA forum thread](https://xdaforums.com/t/app-2-3-mixplorer-v6-x-released-fully-featured-file-manager.1523691/) and a Google Drive folder. While the software is top-tier, its manual distribution model poses several challenges:

- **Manual Overhead**: Requires checking XDA or Drive repeatedly for updates.
- **In-App Updater Storage Waste**: MiXplorer's native updater leaves leftover downloaded APK files in internal storage.
- **Missing Single Index**: No unified hub exists displaying all add-ons and architecture variants side-by-side.
- **Obtainium Support**: Package managers like Obtainium cannot track raw XDA forum posts natively.

This repository automates the entire process: a GitHub Action runs daily to inspect the developer's Google Drive, downloads new APK releases, extracts version metadata, and publishes structured GitHub Releases automatically.
